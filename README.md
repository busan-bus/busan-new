# 오늘의 시내버스 주요 뉴스

기사 여러 개를 사진·제목·짧은 요약으로 모아, 고정 주소 하나로 공유하는 간단한 뉴스 모음입니다. 최신 날짜부터 표시되고, 지난 기사도 날짜별로 남습니다. 보내주신 인포크링크 페이지의 날짜별 기사 모음을 기준으로 만들었습니다.

## 사용 방법

1. ‘기사 올리기’에서 날짜와 기사 주소를 입력합니다. 여러 개면 ‘기사 하나 더 추가’를 누릅니다.
2. 링크만 넣어도 됩니다. 내용을 직접 바꾸고 싶은 경우에만 ‘직접 수정하기 (선택)’를 엽니다.
3. ‘등록하기’를 누르고 열린 GitHub 화면에서 Create를 눌러 등록을 완료합니다. 지정 편집자 계정의 등록만 반영됩니다.
4. 수 분 후 사이트를 확인하고, 항상 같은 주소를 카카오톡으로 보냅니다.

제목·사진·언론사는 발행할 때 기사 페이지에서 가져옵니다. 요약은 기사 본문의 문장을 짧게 발췌하며, 본문을 읽지 못하면 언론사의 기사 소개를 사용합니다. 언론사에서 차단하거나 항목을 제공하지 않으면 직접 넣어야 합니다. 새로운 문장을 AI로 작성하는 방식은 아닙니다. 본문 자동 발췌인지 언론사의 기사 소개인지 카드에 구분해 표시합니다. 사진이 열리지 않으면 빈 사진 안내를 표시합니다.

## GitHub Pages에 처음 게시하기

1. 기본 브랜치가 `main`인 저장소를 만들고 Issues를 활성화합니다.
2. 이 폴더의 파일을 올립니다. `.github/workflows/pages.yml`도 포함해야 합니다.
3. Settings → Pages → Source를 GitHub Actions로 선택합니다.
4. Actions의 ‘뉴스브리핑 발행’을 실행하고 Pages에서 실제 게시 주소를 확인합니다.
5. 개인 저장소는 소유자 계정이 편집자입니다. 조직 저장소나 다른 편집자는 `config.json`의 `allowed_editors`에 정확한 GitHub 계정명을 넣습니다.

실제 GitHub 연결·배포는 아직 완료되지 않았습니다. `preview.html`은 게시 전 화면 확인용입니다. 예시에는 제공하신 인포크 페이지의 기존 기사 세 건과 원문을 읽고 작성한 짧은 요약을 넣었습니다. 날짜는 해당 페이지의 공유일이며 최신 뉴스가 아닙니다. 예시 사진은 언론사 원격 주소를 사용하므로 인터넷 연결이 필요합니다.

## 지난 기사 수정·보관

원본은 GitHub Issues에 저장됩니다. 등록 글의 JSON을 수정하면 반영됩니다. 글을 닫으면 사이트에서 제외하고 다시 열면 복원합니다. 같은 날짜의 여러 등록은 함께 표시하고 동일한 기사 주소는 중복 표시하지 않습니다. 브라우저 초안만 이 기기에 저장되며, 실제 등록한 기사는 모든 기기에서 같은 목록으로 보입니다.

사이트는 공개 뉴스 공유용입니다. 기사 전문은 원문에서 읽도록 연결합니다. 사진은 언론사에서 제공하는 원격 대표사진 주소를 사용하며 사진 원본을 재배포하지 않습니다.

## 확인 명령

- `python scripts/build.py --demo --no-metadata`: 화면 예시 생성
- `python -m unittest discover -s tests -v`: 날짜·권한·기사 병합·사진·메타데이터 처리 검증

휴대폰 기본 공유 메뉴의 카카오톡 선택 또는 링크 복사를 지원합니다. 카카오 전용 SDK는 사용하지 않습니다. 카카오톡의 링크 미리보기 표시는 수집·캐시 정책에 따라 달라질 수 있습니다.

자동으로 가져온 기사 정보는 `data/metadata-cache.json`에 보관하여 다음 발행 때 기사를 다시 읽지 못해도 이전 내용을 유지합니다. 이 파일을 갱신하려면 Actions의 저장소 쓰기 권한이 필요합니다. main 브랜치 보호 규칙으로 쓰기가 금지되어 있으면 해당 발행 작업이 실패하며, 조직 정책에 맞는 별도 저장 방식 설정이 필요합니다.

검증: 자동 입력·본문 발췌·사진 추출·이전 정보 유지 등의 17개 테스트를 통과했습니다. 스카이데일리와 부산일보의 제공된 기사 주소에서 제목·사진·요약 추출을 확인했습니다. 로컬 네트워크는 HTTP 프록시 방식이므로 고정된 두 언론사 주소만 허용한 테스트 경로로 확인했으며, 배포 코드의 임의 URL 검사와 GitHub Actions·Pages 실행은 실제 연결 후 확인해야 합니다.

## 휴대폰 및 카카오톡 공유

뉴스 화면과 등록 화면을 320·375·430·768px 너비의 브라우저 프레임에서 확인했으며 가로 넘침은 없었습니다. 휴대폰은 기사 한 열, 본문 16px, 주요 버튼 최소 44px로 표시합니다. 실제 휴대폰·카카오톡 앱에서는 게시 후 추가 확인해야 합니다.
